# Deploy LobeHub Server + Postgres on Railway

LobeHub 2 server mode: AI chat and agents with Postgres, Redis and S3

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/lobehub-server-postgres)

## About

LobeHub (formerly Lobe Chat) is an open-source AI agent workspace. It gives you a polished chat UI for OpenAI, Anthropic, Google, DeepSeek, Ollama and dozens more providers, plus agents, knowledge bases with RAG, file uploads, image generation, plugins and team accounts, all self-hosted.

LobeHub 2.x only runs in server database mode, so a real deployment is four services: the app, Postgres with the pgvector and pg_search extensions, Redis, and an S3-compatible object store. This template mirrors the official Docker Compose stack: `lobehub/lobehub:2.2.17`, `paradedb/paradedb:0.25.9-pg17` (Postgres 17 with both extensions preinstalled), `redis:7-alpine` and `rustfs/rustfs:1.0.0-rc.6`. Every secret is generated by Railway, every connection is a variable reference, the RustFS bucket is created automatically on first boot, and the app runs its own migrations. Email/password sign-in works out of the box with no third-party identity provider.

## What gets deployed

| Service | Source | Type |
|---------|--------|------|
| Redis | `redis:7-alpine` | Database |
| LobeHub | `lobehub/lobehub:2.2.17` | Web service |

| Postgres | `paradedb/paradedb:0.25.9-pg17` | Database |

## Environment variables

| Variable | Service | Default | Description |
| --------- | ------- | ------- | ----------- |
| `REDIS_URL` | Redis | - | Private-network URL referenced by LobeHub as ${{Redis.REDIS_URL}}. |
| `REDIS_PASSWORD` | Redis | (secret) | Password for Redis AUTH (passed to redis-server --requirepass by the start command). |
| `ENABLE_ALPINE_PRIVATE_NETWORKING` | Redis | true | Railway flag that makes Alpine/musl DNS resolve *.railway.internal names correctly. |
| `PORT` | LobeHub | 3210 | LobeHub listen port. Railway's healthcheck and edge proxy probe $PORT and the Next.js standalone server reads PORT, so keep it at 3210 (the domain target port). |
| `APP_URL` | LobeHub | - | Public base URL of this LobeHub instance (no trailing slash). Better Auth uses it for cookies, trusted origins and OAuth callbacks. Change it if you attach a custom domain. |
| `HOSTNAME` | LobeHub | 0.0.0.0 | Bind address for the Next.js standalone server. Docker sets HOSTNAME to the container id, which makes Next.js bind a single interface and fail Railway's healthcheck; 0.0.0.0 listens on all interfaces. |
| `JWKS_KEY` | LobeHub | - | Optional. RS256 JWKS JSON used to sign internal and OIDC tokens (desktop app, CLI, mobile sign-in). If empty, the start command generates an ephemeral key on every deploy, so those clients must sign in again after a redeploy. Generate a stable value at https://lobehub.com/docs/self-hosting/environment-variables/auth#jwks-key and paste the single-line JSON here. |
| `REDIS_TLS` | LobeHub | 0 | Redis over the private network is plaintext; keep 0. |
| `REDIS_URL` | LobeHub | - | Private-network Redis URL used for session storage, presigned URL cache and agent config cache. |
| `S3_BUCKET` | LobeHub | - | Bucket name. RustFS creates it automatically on first boot. |
| `S3_REGION` | LobeHub | us-east-1 | Signing region. RustFS defaults to us-east-1. |
| `S3_SET_ACL` | LobeHub | 0 | Keep 0: files are served through short-lived presigned URLs, so the bucket stays private. |
| `AUTH_SECRET` | LobeHub | (secret) | Better Auth session signing secret. Rotating it signs every user out. |
| `S3_ENDPOINT` | LobeHub | - | S3 endpoint of the bundled RustFS service. It must be the public HTTPS domain because the browser uploads directly to presigned URLs built from this value. |
| `SEARXNG_URL` | LobeHub | - | Optional. Private URL of a SearXNG service for web search (for example http://searxng.railway.internal:8080). Add one from the marketplace if you want online search. |
| `DATABASE_URL` | LobeHub | - | Private-network Postgres connection string. The bundled ParadeDB image provides the pgvector and pg_search extensions LobeHub's migrations require. |
| `REDIS_PREFIX` | LobeHub | lobechat | Key prefix in Redis. |
| `GOOGLE_API_KEY` | LobeHub | (secret) | Optional. Google Gemini key; can also be added in Settings > AI Provider. |
| `OPENAI_API_KEY` | LobeHub | (secret) | Optional. Provider keys can also be added per user in Settings > AI Provider after signing in. |
| `DATABASE_DRIVER` | LobeHub | node | Use the node-postgres driver (required for a self-hosted Postgres). Also triggers the automatic Drizzle migrations on every boot. |
| `INTERNAL_APP_URL` | LobeHub | http://localhost:3210 | URL the container uses to call itself for async work (image generation, file processing). Keep it on localhost so those calls never leave the container. |
| `S3_ACCESS_KEY_ID` | LobeHub | - | RustFS root access key (generated on the RustFS service). |
| `ANTHROPIC_API_KEY` | LobeHub | (secret) | Optional. Provider keys can also be added per user in Settings > AI Provider after signing in. |
| `KEY_VAULTS_SECRET` | LobeHub | (secret) | Encrypts provider API keys and other secrets stored in Postgres. Set once and never rotate, or stored keys become unreadable. |
| `AUTH_ALLOWED_EMAILS` | LobeHub | - | Strongly recommended. Comma-separated emails or domains allowed to register (for example you@example.com,example.com). Leave empty and anyone who finds the URL can create an account and use your provider keys. |
| `S3_ENABLE_PATH_STYLE` | LobeHub | 1 | RustFS serves buckets as path-style URLs (endpoint/bucket/key). |
| `S3_SECRET_ACCESS_KEY` | LobeHub | (secret) | RustFS root secret key (generated on the RustFS service). |
| `LLM_VISION_IMAGE_USE_BASE64` | LobeHub | 1 | Send images to vision models as base64 instead of a URL the provider has to fetch (mirrors the upstream compose). |
| `PORT` | RustFS | 9000 | S3 API port. RustFS binds [::]:9000 by default (dual-stack). Railway's healthcheck and the public domain probe $PORT, so keep it at 9000. |
| `RUSTFS_BUCKET` | RustFS | lobe | Bucket the start command creates on boot (idempotent). Referenced by LobeHub as S3_BUCKET. |
| `RUSTFS_VOLUMES` | RustFS | /data | Data directory (the Railway volume). |
| `RUSTFS_ACCESS_KEY` | RustFS | - | Root access key. Referenced by LobeHub as S3_ACCESS_KEY_ID. |
| `RUSTFS_SECRET_KEY` | RustFS | (secret) | Root secret key. Referenced by LobeHub as S3_SECRET_ACCESS_KEY. |
| `POSTGRES_DB` | Postgres | lobechat | Database name. The ParadeDB bootstrap installs pgvector and pg_search into it on first init. |
| `DATABASE_URL` | Postgres | - | Private-network connection string (includes port). |
| `POSTGRES_USER` | Postgres | (secret) | Database superuser. |
| `POSTGRES_PASSWORD` | Postgres | (secret) | Generated database password. |
| `DATABASE_PUBLIC_URL` | Postgres | - | Public URL via the TCP proxy (for psql / GUI clients). |

## Configuration

- **Start command:** `sh -c 'docker-entrypoint.sh redis-server --requirepass "$REDIS_PASSWORD" --save 60 1 --appendonly yes --dir /data --bind :: 0.0.0.0'`

- **Start command:** `sh -c 'if [ -z "$JWKS_KEY" ]; then echo "JWKS_KEY not set; generating an ephemeral RS256 key for this deployment (set JWKS_KEY to keep OIDC/desktop sign-ins across redeploys)"; export JWKS_KEY="$(echo Y29uc3QgYz1yZXF1aXJlKCdjcnlwdG8nKTtjb25zdCB7cHJpdmF0ZUtleX09Yy5nZW5lcmF0ZUtleVBhaXJTeW5jKCdyc2EnLHttb2R1bHVzTGVuZ3RoOjIwNDh9KTtjb25zdCBqPXByaXZhdGVLZXkuZXhwb3J0KHtmb3JtYXQ6J2p3ayd9KTtqLnVzZT0nc2lnJztqLmFsZz0nUlMyNTYnO2oua2lkPWMucmFuZG9tQnl0ZXMoOCkudG9TdHJpbmcoJ2hleCcpO3Byb2Nlc3Muc3Rkb3V0LndyaXRlKEpTT04uc3RyaW5naWZ5KHtrZXlzOltqXX0pKQo= | /bin/base64 -d | /bin/node)"; fi; exec /bin/node /app/startServer.js'`

- **Start command:** `sh -c '( until curl -sf http://127.0.0.1:9000/health >/dev/null 2>&1; do sleep 2; done; curl -s -o /dev/null -w "bucket $RUSTFS_BUCKET create: HTTP %{http_code}\n" -X PUT --aws-sigv4 "aws:amz:us-east-1:s3" --user "$RUSTFS_ACCESS_KEY:$RUSTFS_SECRET_KEY" "http://127.0.0.1:9000/$RUSTFS_BUCKET" ) & exec /entrypoint.sh rustfs'`

- **Volume:** `/var/lib/postgresql/data`
